# Отладка сценариев (тесты)

Эффективно разрабатывать правила-сценарии обработок сразу вместе с тестом.

1. Установить 1testrunner для возможности модульного тестирования сценариев обработки

```sh
opm i 1testrunner
```

2. Первично запустить все тесты репозитария командой: `1testrunner -runall tests`. `tests` это папка в которой находятся все тесты. Не должно быть ошибок, как до, так и после разработки сценариев.

Запуск всех модульных тестов репозитария:

```sh
1testrunner -runall tests
``` 

Запуск тестов целиком выбранного файла:

```sh
1testrunner -run .\tests\ТестПроверкаСценариевОбработки.os
``` 

Точечный запуск определенного теста из файла:

```sh
1testrunner -run .\tests\ТестПроверкаСценариевОбработки.os "ТестДолжен_ПроверитьЧтоВыполняютсяПринудительноУказанныеЛокальныеСценарии"
``` 

3. Если необходимо написать тест к правилам (сценариям обработкам), то использовать файл из каталога `tests\*.os`. Например: `tests\ТестПроверкаСценариевОбработки.os`

4. Для отладки теста может быть установлен набор расширений: 1C (BSL) Extension Pack. Чтобы запускать и отлаживать правила-сценарии обработок через 1testrunner в отладчике OScript, можно настроить launch.json в vscode (пример ниже).

Пример настройки для Windows:

```JSON
{
    // .vscode/launch.json
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Отладка 1Script",
            "type": "oscript",
            "request": "launch",
            "program": "<Путь к папке Onescript>\\lib\\1testrunner\\src\\main.os", // Пример пути в Windows к main.os
            "args": ["-run", "${file}"],
            "cwd": "${workspaceFolder}",
            "env": {},
            "runtimeExecutable": null,
            "runtimeArgs": [],
            "debugPort": 2801
        }
    ]
}
```

5. Тест должен покрывать позитивные и негативные сценарии работы правил. Плюс необходимо учесть в тестах проверку исходного кода для Конфигуратора и EDT.
6. В папке `tests\fixtures` необходимо хранить заготовки входных данных для тестов.
